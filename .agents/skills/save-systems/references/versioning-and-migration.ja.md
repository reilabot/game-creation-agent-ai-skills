# バージョン管理、移行、および堅牢性を保存

 保存は、それらを作成したコードよりも長く保存されます。 v1.0 で保存したプレーヤーは、アップデート後に v1.4 で
がロードされることを期待します。最初のリリースからのスキーマの進化を計画します。

 ## バージョン フィールドは交渉不可です

 すべての保存に整数 `version` (または
が必要な場合は構造化 `{major, minor}`) をスタンプします。ロード時:

 1. `version` を読み取ります。
2. 実行中のビルドより**新しい**場合 → 明確なメッセージ
(「この保存は新しいバージョンからのものです」) を表示して拒否します。知らない分野については推測しないでください。
3. **古い**場合 → 現在の
バージョンと一致するまで、移行を順番に実行します。
4. 検証してインスタンス化します。

 単一の単調整数を優先します。セマンティックな 2 部構成のバージョンは、リリース ライン間で本当にブランチ保存の互換性がある場合にのみ、
 の価値があります。

 ## 移行チェーン

 各移行を **純粋関数** `vN -> vN+1` として記述し、順番に適用します。
これにより、小さなテスト可能な手順で到達可能なすべてのバージョンが最新に保たれます。
 の巨大な「何かを最新のものに変換する」機能は決してありません。

```python
SAVE_VERSION = 4

MIGRATIONS = {
    1: migrate_1_to_2,   # added "flags" map
    2: migrate_2_to_3,   # split "name" into first/last
    3: migrate_3_to_4,   # inventory items gained a "durability" field
}

def upgrade(data):
    v = data.get("version", 1)
    while v < SAVE_VERSION:
        data = MIGRATIONS[v](data)
        v += 1
        data["version"] = v
    return data
```

ガイドライン:

 - **追加の変更は簡単です**: デフォルトの新しいフィールド。移行では、
 が古い保存のデフォルトを挿入するだけです。
- **名前変更/再構築**: 移行での移動/変換。ゲーム コードでは古い
と新しい名前の両方を決して読み取らないでください。
- **削除されたフィールド**: 後のステップできれいな形状が表示されるように、移行にフィールドをドロップします。
- **古い移行を永久に保持します。** `migrate_1_to_2` を削除すると、すべての v1
保存が無効になります。保存コストが安く、忠実な記録を残さなければなりません。
- **チェーンをテスト**: 出荷された各バージョンからの実際の保存のコーパスを保持し、変更のたびに
がそれらをロードすることをアサートします (これが回帰ネットです)。

 ## バックアップとロールバック

 - 上書きする前に、現在の保存を `*.bak` にコピーします。
プライマリのロードが失敗した場合は、自動的にバックアップを試みます。
- 自動保存の場合、小さなリング (autosave_0..2) を回転させて、間違った自動保存によって
唯一の最近の状態が破壊されないようにします。
- ペイロードのチェックサム/ハッシュを考慮して、切り詰めや破損を検出します。
(決心したローカル プレイヤーが常に打ち負かすことができる改ざん防止とは異なります)。

 ## フォーマットのトレードオフ

 |フォーマット |長所 |短所 | | の場合に使用します。
|---|---|---|---|
| JSON / テキスト |人間が判読可能、デバッグ可能、差分可能、簡単な移行 |より大きく、より遅く、簡単に編集可能 |デフォルト;ほとんどのゲーム |
|バイナリ（エンジン） |コンパクト、高速、やや不透明 |デバッグ/移行が難しく、バージョンが脆弱 |大規模な状態、パフォーマンスが重要 |
|キー/値ストア |シンプルで堅牢なキーごと |構造なし、手動スキーマ |設定、小フラグセット |
|クラウド KV (例: データストア) |クロスデバイス |クォータ、レイテンシー、競合 |オンライン/クロスデバイス保存 |

 ディスク上の形式が何であれ、**メモリ内の辞書/構造体**を
正規形状として保持し、境界で (逆) シリアル化します。その後、移行はフォーマット固有のバイトではなく、そのニュートラルな形状の
で実行されます。

 ## ロード時の検証チェックリスト

 - 必要なキーが存在します。型が正しい (文字列、数値、ブール値)。
- 正常な範囲内の数値 (NaN/無限大なし、hp ≥ 0、範囲内のインデックス)。
- 現在のコンテンツに列挙値/ID 値がまだ存在しています (パッチ
で削除された項目 ID は処理する必要があります。削除するか置き換えてください。クラッシュしないでください)。
- 参照解決 (クエスト ID は既知のクエストを指します)。
- 失敗した場合: ログに記録し、バックアップに戻り、他のすべてが失敗した場合は、壊れた状態を静かにロードするのではなく、*大声で*
をプレーヤーに失敗させます。

 ## 何を保存するか、再計算するか

 - **保存** 権限のある、派生不可能な状態: 選択肢、ロック解除されたフラグ、RNG
シード、インベントリ、ポジション。
- ロード時に派生データを **再計算**します (ベース + モディファイアからの完全な統計テーブル、シードからの
プロシージャ マップ)。派生データを保存すると、パッチ内で
式が変更されたときに非同期が発生し、ファイルが肥大化します。
