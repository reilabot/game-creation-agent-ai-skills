# プラットフォーマー フィール チューニング (深さ)

 `SKILL.md` のコントローラーの背後にあるより深い詳細。すべてのスニペットはエンジンに依存しない
疑似コードです。計算は標準的な運動学であり、あらゆるエンジンに移植できます。 *結果*
(高さのタイル、頂点までの秒数) によって調整し、物理値を読み取ります。

 ## 1. ジャンプ物理の導出

 ジャンプは単なる発射動作です。設計者が実際に感じることができる 2 つの値 (
 **ピーク高さ** `h` と **ピーク到達時間** `t`) を選択し、残りを解決します。
y 軸が下を向いている場合 (ほとんどの 2D エンジン):

```
gravity        g  = 2h / t²
jump_velocity  v0 = -2h / t          # negative = upward
peak reached after t seconds; total airtime ≈ 2t (symmetric gravity)
```

非対称重力により、ピークの高さを変えることなく、上昇よりも下降がよりきびきびします:

```
rise_gravity = g
fall_gravity = g * fall_multiplier   # 1.5–2.0 feels good
# airtime shortens; the arc looks like a fast, weighty drop after a quick pop up.
```

ジャンプ速度がわかっていて高さが必要な場合: `h = v0² / (2g)`。

## 4. コーナー修正 (天井と棚のナッジ)

 上昇ジャンプでコーナーが 1 ～ 2 ピクセルクリップされると、プレイヤーはそれをゲームが
「スティッキー」であると読み取ります。ジャンプデッドを止める代わりに、彼らを押しのけて通り過ぎてください:

```python
# On hitting a ceiling while rising, if only the outer 1–4 px are blocked,
# shift the body sideways into the free space and keep the upward velocity.
if blocked_overhead and velocity.y < 0:
    for offset in (1, 2, 3, 4):            # check small horizontal nudges
        if free_at(position + sideways * offset):
            position += sideways * offset
            break                          # keep rising; don't zero velocity.y
```

着地エッジ (数ピクセルの「棚つかみ」/スナップ) に関する同じアイデアにより、プラットフォームが寛大に感じられます。

 ## 5. 一方向プラットフォームとドロップスルー

 - プラットフォームの衝突を一方向としてマークします (プレーヤーが上にいて、
 が下に移動している場合のみ点灯)。エンジンはこれを直接公開します。手で回転させないでください。
- **ドロップスルー:** プレイヤーが一方通行のプラットフォームで Down + Jump を押したままにすると、その
コリジョンを約 0.1 ～ 0.2 秒 (またはプレイヤーの頂点がプラットフォームの下を通過するまで) 無効にしてから、再度有効にします。

 ## 7. カメラは

 - **デッドゾーン:** カメラが反応する前にプレイヤーが移動できる四角形。ジッターを停止します。
- **先読み:** プレイヤー
が何が来るかを認識できるように、カメラ ターゲットをモーション/向きの方向にオフセットします。オフセットをLerpします。スナップしないでください。
- **スムージング:** 固定分数ではなく指数関数 `lerp(cam, target,
1 - exp(-k*dt))` を使用してカメラをターゲットに向かって移動するため、フレーム レートに依存しません。
- **クランプ:** レベル外の空間が表示されないように、カメラの四角形をレベル境界内に保ちます。
- **垂直方向の注意:** 通常のジャンプ中にロックするか、垂直方向のフォローを遅くします。ホップするたびに揺れることを避けるために、
 の高さの大きな変化 (穴に落ちる、登る) でのみ Y に従ってください。

 ## 8. ティーチングとペーシング (`level-design` へのハンドオフ)

 - 1 つのメカニズムを単独で導入し、プレイヤーに安全に練習させてから*、それを既知のメカニズムと組み合わせます。同じ危険に 2 つの新しいものを決して導入しないでください。
- 致命的な危険の最初のインスタンスを、失敗が少ない場所 (チェックポイントの近く、
 では再トラバースが不要) に配置します。
- チェックポイント間のセグメントを初期は短くし、後で長くします。リスポーンは即時である必要があります。
