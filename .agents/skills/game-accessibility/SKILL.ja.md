 # game-accessibility

 ## スコープ

 検出されたエンジンの規則を維持しながら、この責任を負います。隣接する専門家を交代させないでください。明示的なデータとセマンティック イベント コントラクトを通じて構成されます。

 ## ワークフロー

 1. ファイルを変更する前に、プロジェクト プロファイル、プレイヤー向けの目標、制約、ターゲット ハードウェア、および既存のテストを読み取ります。
2. 測定可能な動作、所有権、調整可能なパラメータ、失敗例、および再生可能な最小増分を示します。
3. バージョンと利用可能なツールを検出した後、エンジン ネイティブ API を介して実装します。シミュレーションの真実をプレゼンテーションから切り離してください。
4. データ スキーマまたはセマンティック イベントを使用して隣接するシステムを接続します。安定したコントラクトが機能する場合は、システム間の直接の依存関係を回避します。
5. アクセシビリティ マトリックス、デフォルト、永続性、およびユーザー テストを作成します。

 ## クオリティ ゲート

 ターゲットの入力とプラットフォームで代表的なプレイヤー ジャーニーとエッジ ケースをテストします。利用可能なログ、スクリーンショット/ビデオ、プロファイラー データ、保存、またはネットワーク トレースをキャプチャします。ファイルが存在するということは、正しい動作を証明するものではありません。

 ## 境界

 破壊的なデータ操作、購入、資格情報の使用、ストアの公開、運用展開、または元に戻せない外部変更の直前に明示的な承認を必要とします。決して秘密を埋め込まないでください。最終的な承認を `gamedev-quality-gate` 経由でルーティングします。
